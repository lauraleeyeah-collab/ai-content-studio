## 一、产品概述

### 1.1 一句话定位

**同一份选题资产，一次生产，按 6 个平台规则自动适配输出，发布后用数据反哺下一次生产。**

### 1.2 产品愿景

从「小红书爆款拆解与选题文案生成工具」（单一平台、图文为主）升级为「AI 超级自媒体工具」：覆盖图文 + 视频两大内容形态，支持小红书、微信公众号、微信问一问、微信视频号、知乎、抖音 6 个渠道，成为创作者个人的「内容中台」。

### 1.3 核心差异化（与竞品的区别）

竞品做「一键生成」和「多平台复制分发」；本产品做「**从选题到平台适配的智能决策**」：

- 内置 6 平台规则知识库（算法权重、内容偏好、红线、AI 标注要求）。
- 同一素材按平台逻辑改写（不是复制粘贴），并给出每个版本的改写理由。
- 发布前合规检查（极限词、站外导流、AI 标注、行动指令缺失）。
- 发布后数据回填，归因到选题/标题/封面/渠道，指导下一次生产。

### 1.4 价值主张

| 用户角色 | 痛点 | 本产品价值 |
| --- | --- | --- |
| 个人创作者 | 一条内容要手动改 6 个平台版本，格式、话术、封面全不同 | 自动产出多平台版本 + 发布清单，节省 70% 重复劳动 |
| 自媒体运营（一人成军） | 不知道各平台最新规则，发出去被限流 | 内置规则库 + 发布前合规检查，降低违规风险 |
| 求职期转型者（本人） | 需要可演示、可讲清楚产品逻辑的作品集 | 本地可跑、Demo 模式免 Key 演示、PRD 完整 |

## 二、背景与问题

### 2.1 市场背景（2026）

- 平台分发逻辑全面转向「搜索 + 行为预测」：小红书搜索流量占比超 55%，抖音权重第一是收藏率。
- AI 生成内容强制标注，合规能力成为内容工具的上架前提。
- AI 视频从「能生成」走向「能生产」，创作者愿意为生产级工具付费（可灵单月 2000 万美元收入）。
- 一人成军（OPC）成为主流创作形态，一个人需要同时运营多个平台。

### 2.2 现状问题（原工具）

1. 只覆盖小红书单平台、图文为主，未覆盖视频和多渠道。
2. 缺少平台规则适配：标题、话术、封面不按平台差异化生成。
3. 缺少发布管理：生成完即结束，没有发布清单、合规检查、数据回填。
4. 数据沉淀了但未反哺：历史库有 10+ 张表，但没有「哪个选题/标题/渠道有效」的归因视图。

### 2.3 目标与衡量指标（PRD 级北极星）

- 北极星指标：**单条选题的多平台产出覆盖数**（目标：1 条选题 → ≥3 个平台适配版本）。
- 次要指标：
  - 生产耗时：从选题到 6 平台发布清单，人工干预 ≤3 次，耗时 ≤15 分钟（演示口径）。
  - 合规命中：发布前合规检查拦截率 100%（红线类），误报率 ≤10%。
  - 数据回填：已发布内容数据回填率 ≥80%。
  - 复访与留存：同一用户连续 3 周使用率（个人工具场景，作为自身使用度量）。

## 三、用户画像与核心场景

### 3.1 用户画像（MVP 聚焦）

- **主画像：个人创作者 / 自媒体运营**（1-3 人团队），同时运营 2 个以上平台，每天 1-2 小时内容生产。
- 次画像：求职演示者（本人），需要 30 秒跑通全流程的 Demo 能力。

### 3.2 核心场景

**场景 A：一条选题，六平台发布（P0 主流程）**
1. 在「选题」输入热点笔记或主题 + 人设。
2. 系统产出选题卡片（搜索词、爆款拆解、差异化角度）。
3. 一键生成图文版本（小红书）→ 自动改写为公众号 / 知乎 / 问一问版本。
4. 一键生成视频脚本（分镜、口播、字幕）→ 适配视频号 / 抖音 / 小红书视频。
5. 生成发布清单：每平台标题、正文、标签、封面提示词、发布时间、合规检查结果。
6. 勾选平台 → 导出发布清单（MVP 不做自动发布，手动发布后回填数据）。

**场景 B：爆款归因（P1）**
- 某条内容在小红书收藏率高、抖音完播率低，数据中心给出归因：「标题前 20 字关键词密度不足」「视频缺少显性收藏指令」。

**场景 C：历史复用（P0 沿用）**
- 历史所有选题、文案、脚本、发布记录可检索复用，去重防重复生产。

## 四、功能需求

### 4.1 模块总览

```
工作台（内容日历 / 多账号 / 全渠道概览）
├── 图文工厂：选题 → 标题 → 封面 → 正文 → 互动话术 → 爆款分析
├── 视频工厂：选题 → 脚本分镜(秒级) → 封面 → 标题 → 播放优化 → 互动策略
├── 渠道中心（核心差异化）：6 平台规则库 + 一键多平台改写 + 发布清单 + 合规检查
└── 数据中心：数据回填 / 渠道对比 / 爆款归因 / 历史管理
```

### 4.2 P0（MVP 必须，验证核心价值）

#### 图文工厂（改造现有模块）
| 功能 | 说明 | 复用现有资产 |
| --- | --- | --- |
| 选题分析 | 搜索词分析（标题前 20 字关键词置顶）、爆款拆解、差异化角度 | 现有 5-Agent 流水线 |
| 标题生成 | 按平台生成标题 + 多维评分 + A/B 候选 | 现有标题优化模块 |
| 封面提示词 | 生成 AI 生图提示词（风格、构图、文案位），不直接生图 | 新增 |
| 正文生成 | 按平台风格改写（小红书清单体 / 公众号长文 / 知乎结论先行 / 问一问高密度答案） | 现有文案 Agent + style_guide |
| 互动话术 | 评论区引导话术、收藏理由话术（抖音强制显性指令） | 新增 |

#### 视频工厂（新模块）
| 功能 | 说明 |
| --- | --- |
| 视频选题 | 从图文选题复用或独立生成，输出口播主题 + 搜索词 |
| 脚本分镜（秒级） | 生成分镜表格：时间轴 / 画面 / 口播词 / 字幕 / 转场，支持 30s-3min 模板 |
| 视频标题 + 封面 | 平台差异化生成（抖音钩子型、视频号人设型） |
| 播放优化 | 5 秒完播检查、收藏指令检查、行动指令显性化 |
| 互动策略 | 评论区置顶话术、争议点设计（合规范围内） |

#### 渠道中心（核心差异化，P0 重点）
| 功能 | 说明 |
| --- | --- |
| 6 平台规则库 | 每个平台一张规则卡：算法权重、内容偏好、红线、AI 标注要求、最佳实践；存 SQLite 可迭代 |
| 一键多平台改写 Agent | 输入素材 → 按平台规则逐平台改写，输出每版本 + 改写理由 |
| 发布清单 | 每平台标题/正文/标签/封面/发布时间/合规结果，一键导出 Markdown |
| 合规检查 Agent | 极限词、站外导流、刷量话术、虚假权威、AI 标注缺失；命中给改写建议 |

#### 数据模型基础（见第五节）

### 4.3 P1（MVP 后 1-2 个迭代）✅ 已实现（2026-08-12）

- **数据中心**：发布记录数据回填（手动输入或 CSV 导入）→ 渠道对比看板 → 爆款归因（选题/标题/封面/渠道四维）。
- **内容日历**：发布计划视图（周视图 + 平台分布），渠道中心发布清单自动同步入日历（`pages/12_内容日历.py`）。
- **多账号**：账号档案（人设、领域、平台绑定），支持切换人设生成（`pages/11_账号中心.py`，各工厂自动使用当前账号人设）。
- **AI 标注自动化**：生成内容自动附带标注模板（6 平台模板表），发布清单强制勾选确认。

### 4.4 P2（远期，不阻塞 MVP）

- 视频生成对接（调用 Seedance/可灵等 API，从分镜脚本直接出片）。
- 自动发布（官方开放平台 API，需合规评估）。
- 团队协作（多人共用人设库与选题库）。
- 插件市场（平台规则卡支持用户自定义）。

### 4.5 不做（明确边界，防 scope 膨胀）

- 不做内容采集爬虫（合规风险，沿用人工粘贴/上传）。
- 不做自动发布（MVP 阶段输出发布清单，手动发布）。
- 不做原生视频剪辑（生成分镜脚本与口播词，不操控剪辑软件）。
- 不做多模型视频生成调度（P2 再评估）。

## 五、数据模型

沿用 SQLite（免部署、个人工具），在现有 10+ 张表基础上新增：

| 表 | 说明 | 关键字段 |
| --- | --- | --- |
| `channels` | 平台规则库 | id, name, algorithm_weights, content_prefs, red_lines, ai_label_required, best_practices, updated_at |
| `content_assets` | 内容资产（选题/图文/脚本统一入口） | id, asset_type(topic/copy/script/cover), channel, title, content, search_keywords, persona_id, created_at |
| `publish_records` | 发布记录与清单 | id, asset_id, channel, final_title, final_content, checklist_json, publish_time, status, created_at |
| `platform_metrics` | 平台数据回填 | id, publish_record_id, channel, views, likes, collects, comments, shares, play_rate, completion_rate, collected_at |
| `channel_rewrites` | 多平台改写版本 | id, source_asset_id, target_channel, rewritten_content, rewrite_reasons, compliance_result, created_at |
| `personas` | 账号人设库 | id, name, domain, tone, style_guide_ref, channels |
| `search_keywords` | 搜索词库 | id, keyword, channel, search_volume, intent, source |

**确定性兜底原则（沿用）**：权重计算、排序、合规命中判定、比例核验全部由 Python 代码完成，LLM 只做主观判断（打分、改写、拆解）。

## 六、Agent 架构

### 6.1 总体结构（在现有 5-Agent 基础上扩展）

```
输入层：粘贴内容 / 上传图片 / 选题关键词 / 人设选择
  ↓
图文流程：
  TopicAnalyzer(选题+搜索词) → HeadlineGenerator(平台标题) → CoverPromptGenerator(封面)
  → Copywriter(平台正文) → InteractionCopywriter(互动话术) → ComplianceChecker(合规)
  ↓
视频流程：
  VideoTopicAnalyzer → ScriptStoryboarder(秒级分镜) → VideoHeadlineGenerator
  → PlayOptimizer(完播/收藏检查) → InteractionStrategist(互动策略) → ComplianceChecker
  ↓
渠道流程（核心差异化）：
  ChannelRewriter(按平台规则改写) → PublishListBuilder(发布清单) → ComplianceChecker(全渠道复核)
  ↓
数据层：DataBackfill(回填) → AttributionAnalyzer(爆款归因) → 历史管理
```

### 6.2 Agent 清单与职责

| Agent | 职责 | LLM 判断 vs 代码计算 |
| --- | --- | --- |
| TopicAnalyzer | 选题拆解、搜索词提取、差异化角度 | LLM 拆解；代码做搜索词排序、去重 |
| HeadlineGenerator | 按平台生成标题 | LLM 生成；代码做前 20 字关键词检查、长度检查、A/B 候选 |
| CoverPromptGenerator | AI 生图提示词 | LLM 生成；代码校验提示词完整度 |
| Copywriter | 平台化正文 | LLM 改写；代码做字数/分段/关键词密度检查 |
| ScriptStoryboarder | 秒级分镜脚本 | LLM 生成分镜；代码做时间轴合计校验（总时长匹配） |
| PlayOptimizer | 完播/收藏检查 | LLM 给建议；代码检查「收藏指令」是否显性出现 |
| ChannelRewriter | 多平台改写 | LLM 改写；代码做红线词扫描、字数限制、结构模板核验 |
| ComplianceChecker | 合规检查 | LLM 语义判断（隐含极限词）；代码做词表硬校验（确定性） |
| AttributionAnalyzer | 爆款归因 | LLM 解读；代码做指标归一化、维度对比排序 |

### 6.3 关键技术决策（沿用 + 新增）

- **LLM 判断 + Python 计算**：所有排序、比例、时间轴、词表校验走代码，杜绝模型算数不稳定。
- **JSON 三级容错**：沿用 `call_llm_json` 的解析/纠错/重试。
- **温度策略**：分析/改写类 0.15-0.35，创作类 0.7-0.8（沿用 config.py 模式）。
- **规则库外置**：平台规则卡存 SQLite + Markdown（可迭代，不硬编码），支持后续按平台版本更新。
- **Demo 模式沿用**：`DEMO_MODE=1` 免 Key 跑通全部新流程，保证面试可演示。

## 七、AI 合规设计（2026 平台强制要求）

1. **强制 AI 标注**：所有 AI 生成内容（图文/脚本/标题）自动附带标注文案模板；发布清单中「AI 标注」为必确认项，未确认不允许导出。
2. **红线词硬校验**：内置极限词/导流/刷量/虚假权威词表（代码级），命中即拦截并给改写建议。
3. **平台差异化规则**：每个平台的红线与标注要求独立存储（小红书 4 条红线、抖音 4 类红线等），不共用一套词表。
4. **行动指令合规**：抖音强制显性「建议收藏」，PlayOptimizer 负责检查；引导互动话术避开诱导性违规表述。
5. **不碰平台反爬**：数据输入全部为人工粘贴/上传/手动回填，工具不含任何采集能力（可写进面试话术：合规优先）。

## 九、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 平台规则频繁变化 | 规则库过期，改写建议失效 | 规则库外置 + 版本号 + 更新记录；规则卡优先沉淀「长期稳定的逻辑」（如权重排序、红线类别） |
| LLM 改写质量不稳 | 平台版本不像该平台的内容 | 结构模板 + 规则卡约束输出；确定性检查（字数、结构、关键词）兜底；人工确认步骤保留 |
| 功能范围膨胀 | MVP 延期 | 严格按 P0 边界（4.5 不做清单）；P1/P2 明确排期 |
| 合规风险（AI 标注遗漏） | 内容被限流/封禁 | 发布清单强制确认 AI 标注；合规检查默认开启不可关闭 |
| 个人工具缺乏真实数据验证 | 归因功能缺样本 | 先支持 CSV/手动回填积累数据；Demo 数据内置 3 套完整示例 |
| 面试演示翻车 | 无 Key 无法跑通 | Demo 模式全流程覆盖新模块；测试用例当演示脚本 |

## 十、评审结论（2026-08-12 已确认）

1. ✅ 视频范围：只做分镜脚本与口播词，不接视频生成 API。
2. ✅ 渠道优先级：6 平台规则库全建，改写流程先验证小红书 + 抖音 + 视频号 3 个高频平台。
3. ✅ 数据中心：接受手动/CSV 回填，不做自动采集。
4. ✅ 命名：正式名「AI 超级自媒体工具」，英文名 AI Super Content Studio（PRD 标题沿用）。

**评审通过，进入实现。里程碑按 M1（图文工厂）→ M2（视频工厂）→ M3（渠道中心）→ M4（数据中心）推进。**
